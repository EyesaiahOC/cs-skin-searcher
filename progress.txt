#### Task 8: Tagger Mode as page 3
All acceptance criteria satisfied. Changes:

  layout. Header row: ⌂ home button, `tagger_progress_label`, `tagger_progress_bar`,
  `tagger_skip_btn`. Body: `tagger_content_stack` (QStackedWidget) with two children —

  scrub slider (`tagger_frame_slider`), frame label, divider, bottom HBox

  right with `tagger_tags_panel` for chip widget), nav row
  (`tagger_prev_btn` / `tagger_save_next_btn`). Stack page 1 (`tagger_complete_page`):
  centred "Tagging Complete!" label (`tagger_complete_label`).
- `application/browser.py`:
  - Added `_TaggerKeyFilter` (application-level `QObject` event filter): fires
    `_tagger_save_and_next` on Ctrl+Enter, `_tagger_prev` on Ctrl+←,
    `_tagger_skip` on Ctrl+Backspace — active only while `pages.currentIndex() == _PAGE_TAGGER`.
  - Added tagger state: `_tagger_queue`, `_tagger_pos`, `_tagger_raw_frames`,
    `tagger_chip_widget` (TagChipWidget injected into `tagger_tags_panel`).
  - Installed resize filter on `tagger_frame_display`.
  - `home_tagger_btn` now calls `_enter_tagger` instead of a bare `setCurrentIndex`.
  - `_enter_tagger`: reloads skins and re-evaluates `untagged_indices()` fresh on each
    entry; if queue non-empty shows active stack and calls `_tagger_load_skin(0)`;
    otherwise shows complete stack.

    `tagger_chip_widget.set_tags()`, loads frames, resets slider to 0.
  - `_tagger_save_and_next`: saves then advances, or shows complete stack if at end.
  - `_tagger_skip`: advances without saving, or shows complete stack if at end.
  - `_tagger_prev`: goes back in session queue.
  - `_tagger_save_current`: writes tags via `SkinStore.save()` and updates in-memory
    `self.skins[store_idx]`.
  - `_go_home`: if leaving tagger page and chips are present → auto-saves; if no chips
    → leaves skin untagged. Detail save still fires when leaving detail page.
  - `_RightArrowFilter` crash: never present in browser.py; standalone tagger.py retains
    it but the merged page 3 does not use it.
- `application/utils.py`: extended QSS selectors for tagger widget names
  (`tagger_skin_name`, `tagger_weapon/collection_label`, `tagger_rarity_label`,
  `tagger_frame_label`, `tagger_frame_display`, `tagger_tags_heading`,
  `tagger_progress_label`) to match the design system styling already applied to the
  detail-view and standalone tagger equivalents.

#### Task 2: Central skin data layer — SkinStore
- `application/skin_store.py`: new `SkinStore(json_dir)` class with `load_all()`,
  `get(index)`, `save(index, skin)`, `search(query)`, and `untagged_indices()`.
- `search("")` returns all indices; `search("ak-47")` matches by normalized weapon name;
  `search("redline")` matches by name/tag substring.
- `untagged_indices()` returns indices where `tags` is absent or empty.
- `browser.py`: removed `json`/`re` imports, `json_files` field, `_normalize()`,
  and manual load/save/search logic — all delegated to `SkinStore`.
- `tagger.py`: removed `json` import and per-file manual load/save — now uses
  `SkinStore.load_all()`, `untagged_indices()`, `get()`, and `save()`. Session queue
  renamed from `current_index`/`json_files` to `queue_pos`/`queue`.
- Tests: `tests/test_skin_store.py` — 9 tests covering all acceptance criteria.
